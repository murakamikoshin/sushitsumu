# 釣り合いを測る道具

配布物（index.html）は一切変えずに、遊びの釣り合いだけを数える仕掛け。
実時間を待たずに早送りできるので、1 戦がおよそ 2 秒で終わる。

    node make-lab.mjs                       # index.html に覗き窓を足した lab.html を作る
    node sim.mjs 100 normal runs.json       # 100 戦まわして書き出す
    node feas.mjs                           # 「そもそも最後まで行けるのか」を組んで確かめる
    node mech.mjs                           # 特定の場面だけを再現して見る

- `vclock.js` … rAF と setTimeout を自前で回す仮想時計。実時間を待たない。
- `bot.js`   … 貪欲な打ち手。合体を最優先し、山が落ち着くまで待ってから置く。
- `lab.html` は作業用の写しで、覗き窓（`window.__dbg`）が付いている。配らない。

`sim.mjs` は `PW=/opt/pw-browsers/...` の chromium を直に叩く。
環境が違うときは `sim.mjs` の executablePath を直すこと。

## 使う前に

    cd tools/sim && npm i playwright-core

`sim.mjs` の `executablePath` は環境の chromium に合わせて直す。

### W 金の桶（金の桶同士の合体）について

出す気で置いてある。出ないのではなく、bot では届かない。

    金の桶 二個に要る手数（無駄ゼロの理想値）   275 手
    bot が生き延びられる手数（最大）            390 手
    bot が金の桶 一個に使う手数（中央値）       255 手（理想値 138 手の 1.9 倍）

bot は貪欲に合体するだけなので、理想値の約 2 倍かけて一個作る。
二個目に届くには、bot より 1.5 倍ほど効率よく打つ必要がある。
山を整えて置ける人だけが届く、という置き方。

物理的に成立することは `wgold.mjs` で直に確かめてある。

    node wgold.mjs

金の桶を二つ直に置いて、共存するか・触れれば合体するかを見る。
桶の内寸 336 に対して金の桶は 150 なので、二つ並べて余りが 36 出る。
（168 だった頃は余り 0 で、間に何か一つでもあると押し出されていた）

### 番付の当たり方（上と同じ 60 戦）

| 段 | しきい値 | 当たり | 前の当たり |
|---|---|---|---|
| 見習い職人 | 0 | 0% | 0% |
| 追い回し | 9,000 | 0% | 0% |
| 若手職人 | 20,000 | 7% | 6% |
| 中堅職人 | 32,000 | 28% | 32% |
| 花板 | 44,000 | 40% | 40% |
| 大将 | 56,000 | 17% | 14% |
| 伝説のすし職人 | 69,000 | 8% | 8% |

一戦が短くなったぶん点も 2 割下がったので、前と同じ当たり方になるよう
しきい値を取り直した。bot は人より上手いので、下二段に落ちない。
人が遊ぶぶんには下二段が効いてくる、という前提の並び。

## 振って比べる

    node sweep.mjs 40          # cands.json に並べた候補を順に回す

`cands.json` の各行で、配布物を触らずに次を差し替えられる。

| 鍵 | 何を振るか |
|---|---|
| `sizes` | 段ごとの寸法の倍率（11 個） |
| `spawn` | 降ってくるネタの重み |
| `btop` | 桶の縁の高さ（小さいほど桶が深い） |
