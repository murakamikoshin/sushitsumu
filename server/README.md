# すし積む 番付サーバー

Cloudflare Workers + D1。無料枠に収まる規模なので、運営費は 0 円のまま
置いておける。クレジットカードの登録も要らない。

## 無料枠との付き合い方

**Cloudflare の無料枠はアカウント単位で、そのアカウントの Workers と D1
すべてで分け合う。** 別プロジェクトを同じアカウントに置いているなら、
枠はこれと共用になる。ただし DNS・CDN・Pages（静的配信）は Workers の
呼び出しも D1 の行も使わないので、そちらとは食い合わない。

一人が一度遊び、点を送り、番付を一度見た時の実測：

| | 使う量 | 無料枠 | 頭打ち |
|---|---|---|---|
| 呼び出し | 2 | 1日 10万 | 1日 5万人 |
| 読んだ行 | 221 | 1日 500万 | 1日 22,624人 |
| 書いた行 | 1 | 1日 10万 | 1日 10万人 |

**効いてくるのは読んだ行数で、1日 2万2千人ぶん。** 内訳は、順位を数える
のに上位100件まで見るのが 200行、番付の一覧が 20行、自分の行が 1行。

2026年9月1日から、D1 は上限を超えると問い合わせを本当に断るように
なった（それまでは緩かった）。共用アカウントでこれを踏むと、隣の
プロジェクトまで止まる。心配なら SCAN（worker.js）を 50 に下げれば
読む行が半分になる。「100位圏外」が「50位圏外」になるだけ。

## 置き方

Node.js が入っていること。Cloudflare のアカウントは既存のもので構わない
（新しく作る必要はない）。

```sh
npx wrangler login          # ブラウザが開くので、置きたいアカウントで許可する
node server/setup.mjs       # あとは全部やる
```

`setup.mjs` は、データベースを作り、その id を `wrangler.toml` に書き込み、
表を用意し、Worker を上げるところまでやって、最後に URL を出す。
何度流しても構わない（二度目からは既にあるものを使い回す）。
Windows・Mac・Linux のどれでも同じコマンドで動く。

手でやるなら：

```sh
cd server
npx wrangler d1 create sushitsumu                              # 出た uuid を wrangler.toml の database_id へ
npx wrangler d1 execute sushitsumu --remote --file=./schema.sql -y
npx wrangler deploy                                            # workers.dev の URL が出る
```

初回の `deploy` では workers.dev の名前を決めるよう聞かれることがある。

**一つのログインで複数のアカウントを扱っている場合**は、どれに置くか
聞かれる。迷わせたくなければ `wrangler.toml` の `account_id` に書いておく。

置けたか確かめる：

```sh
curl 'https://<出てきたURL>/top?kind=normal&mode=all&limit=5'
# → [] が返れば動いている（まだ誰も載っていないので空）
```

出た URL を `index.html` の

```js
var RANK_API  = '';      // 例 'https://sushitsumu-rank.xxxx.workers.dev'
```

に入れれば、そちらを見にいくようになる。空のままなら、これまで通り
アーティファクトの共有データベースを使う（それも無ければ番付ごと隠れる）。

置き場所を絞りたくなったら `wrangler.toml` の `ALLOW_ORIGINS` に
ゲームの URL をカンマ区切りで並べる。

## 口

| | |
|---|---|
| `GET /top?kind=normal\|order&mode=day\|all&day=YYYY-MM-DD&limit=20` | 上位一覧 `[{id,name,score}]` |
| `POST /submit` `{id,name,score,kind,day,log}` | 自己ベストの更新（`log` の辻褄を見てから入れる）。順位 `{rankDay,rankAll,scan}` を返す |

`kind` と `mode` で見る列が変わる。お任せは `best` / `dayBest`、
お品書きは `bestO` / `dayBestO` で、四つの番付は互いに混ざらない。

## 決めごと

- **一人一行。** 遊んだ回数ではなく人数でしか行が増えないので、無料枠を食い潰さない。
- **順位はサーバーで数えて返す。** ゲーム側が一覧を二度引かずに済み、
  一回の登録が 3 呼び出し・421行 から 1 呼び出し・201行 になる。
- **`/submit` は text/plain で受ける。** 中身は JSON だが、この型なら
  ブラウザが前置きの OPTIONS を投げないので、呼び出しがもう一つ減る。
- **日付はサーバー側の日本時間で切る。** 客の時計を信じると日替わりがばらつく。
- **列名は表から引いた定数しか SQL に入れない。** 外から来た文字列は必ず bind に回す。
- **点数は 0〜1000万に丸める。** 名前は制御文字を落として12文字まで。表示側も `textContent`。

## 手順の照合（verify.js）

`/submit` には点だけでなく、一手ごとの控え（`log`）が付いてくる。
`verify.js` がそれを頭から辿り直して、帳尻の合わない申告を弾く。

物理まで再現すれば一番堅いが、それには Matter.js を回す必要があって、
無料枠の CPU（1呼び出し 10ms）に収まらない。運営費 0 円を崩さない範囲で、
「帳尻が合うか」だけを見ている。具体的には四つ。

1. **出題の並び** — 種から同じ並びを作り直し、落とした物と一致するか
2. **在庫** — 手元に二つ無い物を合体させていないか（負の在庫を許さない）
3. **得点** — 書き留めた出来事から足し直して、申告と一致するか
4. **間合い** — 落とす間隔・連鎖の親・注文の中身が決まりの範囲に収まるか

これを通すには、結局まともに遊ぶか、まともに遊ぶ機械を書くしかない。
点だけ書き換える手はこれで通らなくなる。物理までは見ていないので
「あり得ない置き方だが帳尻は合う」記録は残るが、そこまでやる相手は
既に自動で遊ばせているのと変わらない。

実測（自動プレイ 8戦）では誤って弾いた記録は 0、
照合にかかった時間は最長 1.81ms（無料枠の上限 10ms）。

**verify.js の定数は index.html と同じ値でなければならない。**
片方だけ触ると正しい記録が弾かれる。必ず両方を直すこと。
